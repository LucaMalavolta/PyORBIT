`cheops_factormodel` uses the same diagnostic vectors and coefficients as
[`cheops_detrending`](cheops_detrending.md), but contributes to the
multiplicative normalization component. The resulting diagnostic trend is
multiplied by the dataset-specific `scale_factor`.

## Time and roll-angle options

| Keyword | Default | Effect |
| --- | --- | --- |
| `fit_roll_angle` | `True` | include roll-angle harmonics through order 3 |
| `fit_constant_trend` | `False` | omit `dfdt` and `d2fdt2` |
| `fit_linear_trend` | `False` | include only `dfdt` |

When neither time-trend keyword is enabled, the factor model includes both
`dfdt` and `d2fdt2`. `fit_constant_trend` takes precedence over
`fit_linear_trend`.

The model recognizes `time`, `roll_angle`, `smear`, `deltaT`, `xoff`, `yoff`,
`bg` and `contam` ancillary columns. Optional missing columns contribute zero.
The default fixed value of `scale_factor` is one; it must be given boundaries
or a prior if it is intended to vary.

## Example

```yaml
inputs:
  CHEOPS_visit:
    file: datasets/CHEOPS_visit.dat
    ancillary: datasets/CHEOPS_visit_ancillary.dat
    kind: Phot
    models:
      - transit_model
      - cheops_factor

models:
  cheops_factor:
    model: cheops_factormodel
    fit_roll_angle: True
    fit_linear_trend: True
    boundaries:
      scale_factor: [0.8, 1.2]
      dfdt: [-0.1, 0.1]
```

Use only one unconstrained normalization component for a given light curve, or
apply informative priors, to avoid degeneracy with a separate
`normalization_factor`.

No dedicated CHEOPS factor-model configuration is currently present in the
[PyORBIT examples repository](https://github.com/LucaMalavolta/PyORBIT_examples);
the snippet is a minimal configuration sketch.
