# `orbitize` interface

The `orbitize` model passes relative astrometry and, optionally, Hipparcos/Gaia
absolute-astrometry products to the likelihood routines provided by
[`orbitize!`](https://orbitize.readthedocs.io/). It can be combined with the
PyORBIT radial-velocity likelihood and supports more than one planet.

## Requirements

- external packages: `orbitize` and `astropy`
- an external dataset in the input format accepted by `orbitize.read_input`
- stellar `mass` in solar masses and `parallax` in milliarcseconds
- planet mass, inclination, longitude of the ascending node and the remaining
  orbital elements

The dataset must be declared with `external: True` and `kind: orbitize`.

## Optional absolute astrometry

| Keyword | Meaning |
| --- | --- |
| `iad_filepath` | Hipparcos intermediate astrometric data file |
| `hipparcos_ID` | Hipparcos identifier; required with IAD or GOST data |
| `gost_filepath` | Gaia Observation Forecast Tool file used for the HGCA likelihood; requires `iad_filepath` |
| `n_planets` | number passed to the Hipparcos likelihood; default `1` |

## Example

The following is adapted from
[`astrometry/HD5388_test02.yaml`](https://github.com/LucaMalavolta/PyORBIT_examples/blob/main/astrometry/HD5388_test02.yaml):

```yaml
inputs:
  RV_data:
    file: HD5388_RV.dat
    kind: RV
    models: [radial_velocities]
  orbitize_file:
    external: True
    file: no_data.csv
    kind: orbitize
    models: [orbitize]

common:
  planets:
    b:
      orbit: keplerian
      use_mass: True
      use_inclination: True
      boundaries:
        P: [100.0, 10000.0]
        M_Me: [100.0, 3000.0]
        e: [0.0, 0.9]
        i: [0.0, 90.0]
  star:
    star_parameters:
      priors:
        mass: [Gaussian, 1.21, 0.05]
        parallax: [Gaussian, 30.56, 0.09]

models:
  radial_velocities:
    planets: [b]
  orbitize:
    model: orbitize
    iad_filepath: HIP2_HIP004311.d
    gost_filepath: GOST_HIP004311.csv
    hipparcos_ID: 4311
    planets: [b]
```

The example uses `no_data.csv` because its astrometric constraints come from
the IAD/HGCA files. Relative-astrometry analyses should instead provide a
populated `orbitize` input table.

```{warning}
Astrometric orbit modelling requires stellar mass. When transit or
Rossiter–McLaughlin models simultaneously constrain mass, radius and density,
check their parametrization and priors to avoid an over-constrained or
inconsistent stellar model.
```
