# Preparing an RM Revolutions dataset

This page follows the workflow in
[`prepare_datasets_for_RMR_HARPS_G2.ipynb`](https://github.com/LucaMalavolta/RM_revolutions_example/blob/main/prepare_dataset/prepare_datasets_for_RMR_HARPS_G2.ipynb).
The notebook is instrument-specific, but its output dictionary is the format
expected by PyORBIT's expanded dataset reader.

## 1. Read and time-stamp the CCFs

For every exposure, collect:

- the observation epoch, converted to the same BJD time standard and offset
  used by the PyORBIT configuration;
- exposure time in seconds;
- the CCF velocity grid and CCF values;
- the pipeline RV used to shift the CCF to the stellar rest frame;
- enough orbital information to remove the stellar Keplerian velocity.

The HARPS example reads the DRS BJD, CCF RV, FWHM, noise and exposure time from
the FITS headers, then converts BJD UTC to BJD TDB.

## 2. Select transit and master-CCF exposures

Use approximate ephemeris and duration information to define an in-transit
mask. The improved workflow also defines a slightly extended transit mask; its
complement selects the spectra used for the out-of-transit master CCF.

The preparation need not use the final fitted ephemeris, but the master must
not contain appreciable in-transit signal.

## 3. Shift, rebin and normalize

Shift every CCF into a common stellar rest frame and interpolate it onto one
shared, monotonic velocity axis. In the reference notebook the common grid has
a spacing of 0.25 km/s.

Construct the master CCF by combining the selected out-of-transit CCFs. Fit
the continuum outside the line and normalize both the master and every
individual CCF consistently. The example estimates each velocity-bin
uncertainty from the scatter of the continuum difference between an exposure
and the master.

## 4. Choose the data representation

For the improved model, retain the normalized in-transit CCFs as `data` and
store one copy of the normalized master CCF per exposure in `ccf_master`.

For the original formulation, the example uses a transit light curve $F(t)$
to extract a local residual CCF,

```{math}
:label: rmr_local_ccf_extraction

\mathrm{CCF}_{\rm local}(t,v) =
\frac{\mathrm{CCF}_{\rm master}(v)
-F(t)\,\mathrm{CCF}_{\rm observed}(t,v)}{1-F(t)} .
```

Values outside transit are ill-conditioned in this expression, so the
original dataset contains only in-transit rows. Propagate the CCF errors
through the same transformation.

## 5. Write the expanded dataset

The pickle must contain the following keys:

| Key | Shape | Contents |
| --- | --- | --- |
| `data` | `(n_exposure, n_velocity)` | normalized observed CCFs for the improved model, or local residual CCFs for the original model |
| `errs` | same as `data` | uncertainty for every CCF value |
| `ccf_master` | same as `data` | normalized master CCF repeated for every exposure |
| `bjd` | `(n_exposure,)` | exposure epochs |
| `exptime` | `(n_exposure,)` | exposure times in seconds |
| `2nd_axis` | `(n_velocity,)` | common velocity grid |
| `jitter` | scalar or compatible flag array | standard PyORBIT jitter flag |
| `offset` | scalar or compatible flag array | standard PyORBIT offset flag |
| `subset` | scalar or compatible flag array | standard PyORBIT subset flag |

A minimal writer has the following structure:

```python
import pickle

dataset = {
    "data": ccf_data,
    "errs": ccf_errors,
    "ccf_master": master_ccf_2d,
    "bjd": epochs,
    "exptime": exposure_times,
    "2nd_axis": velocity_grid,
    "jitter": 0,
    "offset": -1,
    "subset": -1,
}

with open("ccf_rmr_improved.pkl", "wb") as stream:
    pickle.dump(dataset, stream)
```

Use the same row selection for `data`, `errs`, `ccf_master`, `bjd` and
`exptime`. All matrix rows must have the same velocity grid.

```{warning}
Python pickle files can execute code while loading. Only use datasets produced
by a trusted source, and do not treat pickle as a safe interchange format.
```

## 6. Connect the file to PyORBIT

Declare the pickle as a two-dimensional dataset and keep the model switch
consistent with its representation:

```yaml
inputs:
  RMR_dataset:
    dataset_2d: True
    file: ccf_rmr_improved.pkl
    kind: RV
    models: [rossitermclaughlin_revolutions]

models:
  rossitermclaughlin_revolutions:
    model: rossitermclaughlin_revolutions
    planets: [b]
    limb_darkening: limb_darkening_spectrograph
    use_improved_model: True
```

Before sampling, plot the normalized CCF matrix, master CCF, uncertainty
matrix and residual/local CCF map. Check for inconsistent velocity shifts,
continuum gradients, in-transit spectra included in the master and zero or
non-finite errors.
