# Sinusoid with a common period


`sinusoid_common_period` is useful when several datasets trace the same
periodicity with different amplitudes or phase lags. Only `sine_period` belongs
to the common `sinusoid` object; `sine_amp` and `sine_phase` are created
separately for every attached dataset.

| Parameter | Scope | Unit |
| --- | --- | --- |
| `sine_period` | common | days |
| `sine_amp` | dataset | same as the modelled observable |
| `sine_phase` | dataset | degrees |

## Example

```yaml
inputs:
  RV_HARPS:
    file: datasets/HARPS.dat
    kind: RV
    models: [activity_cycle]
  BIS_HARPS:
    file: datasets/HARPS_BIS.dat
    kind: BIS
    models: [activity_cycle]

models:
  activity_cycle:
    model: sinusoid_common_period
    boundaries:
      sine_period: [10.0, 50.0]
      sine_amp: [-100.0, 100.0]
      sine_phase: [0.0, 360.0]
```

The generic amplitude and phase boundaries are transferred to each dataset.
Dataset-specific overrides can be supplied in subsections named after the
datasets.

No dedicated `sinusoid_common_period` configuration is currently present in
the [PyORBIT examples repository](https://github.com/LucaMalavolta/PyORBIT_examples);
the excerpt is a minimal configuration sketch.
