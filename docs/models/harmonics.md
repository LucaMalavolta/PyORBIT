# Harmonic series

The `harmonics` model describes an additive periodic signal as a selectable
sum of sine and cosine terms,

```{math}
:label: harmonics_equation

f(t) = \sum_{k \in S} A_{S,k}\sin[k\phi(t)+\varphi_{S,k}]
     + \sum_{k \in C} A_{C,k}\cos[k\phi(t)+\varphi_{C,k}] .
```

The base phase is $\phi(t)=2\pi(t-T_0)/P$ when a `T0` parameter is used and
$\phi(t)=2\pi(t-T_\mathrm{ref})/P$ otherwise. Amplitudes are always
dataset-specific, while the period and phase convention can be common or
dataset-specific.

## Model definition and requirements

- model name: `harmonics`
- automatically associated common object: `harmonics`
- default sine harmonics: 1 and 2
- default cosine harmonic: 1
- default period scope: common

The current `harmonics` common object defines amplitudes and independent
phases for harmonic orders 1 through 5. Selections should stay within this
range unless the common-object implementation is extended accordingly.

Parameters are named `amp_S1`, `amp_S2`, ... for sine terms and `amp_C1`,
`amp_C2`, ... for cosine terms. The generic phase parameter is `phase`;
independent phases are named `pha_S1`, `pha_C1`, and so on. Angles are in
degrees and the period uses the same time unit as the input epochs.

## Selecting the harmonic terms

Use `sine_harmonics` and `cosine_harmonics` to include every harmonic from 1
through the requested order:

```yaml
models:
  activity_harmonics:
    model: harmonics
    sine_harmonics: 4
    cosine_harmonics: 0
```

For a non-contiguous selection, use `sine_harmonics_selection` and
`cosine_harmonics_selection`. Set a selection to `None` to disable that
family:

```yaml
models:
  activity_harmonics:
    model: harmonics
    sine_harmonics_selection: [1, 2, 4, 5]
    cosine_harmonics_selection: None
```

This configuration is taken from
[`harmonics/model004_planet_harmonics.yaml`](https://github.com/LucaMalavolta/PyORBIT_examples/blob/main/harmonics/model004_planet_harmonics.yaml)
in the PyORBIT examples repository.

## Period and phase options

Only one phase convention should be selected for a model.

| Keyword | Parameters created | Scope |
| --- | --- | --- |
| no phase keyword | `phase` | dataset |
| `use_common_phase: True` | `phase` | common |
| `use_T0: True` | `T0` | dataset |
| `use_common_T0: True` | `T0` | common |
| `use_independent_phases: True` | one `pha_SN` or `pha_CN` per term | dataset |
| `use_common_independent_phases: True` | one `pha_SN` or `pha_CN` per term | common |

`use_common_period` defaults to `True`; set it to `False` to fit a different
`P` for every dataset. Independent-phase modes are not compatible with the
`T0` modes.

## Complete example

The following excerpt follows the examples in the
[`harmonics`](https://github.com/LucaMalavolta/PyORBIT_examples/tree/main/harmonics)
directory. The period prior and the selected harmonic orders are defined in
the common object, while the amplitudes remain local to `RVdata`.

```yaml
inputs:
  RVdata:
    file: WASP84_RVs.dat
    kind: RV
    models:
      - radial_velocities
      - activity_harmonics

common:
  activity_harmonics:
    model: harmonics
    use_common_phase: True
    sine_harmonics_selection: [1, 2, 4, 5]
    cosine_harmonics_selection: None
    boundaries:
      P: [5.0, 30.0]
    priors:
      P: [Gaussian, 14.30, 1.0]
    spaces:
      P: Linear

models:
  activity_harmonics:
    model: harmonics
    common: activity_harmonics
```

The other example files demonstrate a common `T0`, contiguous harmonic
orders, and common independent phases.
