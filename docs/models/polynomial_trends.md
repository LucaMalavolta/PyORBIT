# Polynomial trends

Polynomial trends can be used to model a smooth variation with time, such as a
long-term instrumental drift or an astrophysical signal whose characteristic
timescale is longer than the dataset. The model evaluated at time $t$ is

```{math}
:label: polynomial_trend_equation

f(t) = \sum_{k=s}^{n} c_k
\left(\frac{t-x_0}{\Delta t}\right)^k ,
```

where $n$ is the polynomial order, $s$ is the starting order, $x_0$ is the
reference time and $\Delta t$ is the value of the `time_interval` keyword.
The reference time is subtracted before evaluating the polynomial to reduce
correlations among its coefficients.

By default, polynomial trends are additive. They can instead be applied as a
normalization model by setting `normalization_model: True`.

## Model definition and requirements

The four implementations use the same polynomial expression but differ in how
their parameters are shared:

| Model name | Parameter scope | Use case |
| --- | --- | --- |
| `polynomial_trend` | `x_zero` and all `poly_cN` coefficients are common to every dataset using the model. | Apply exactly the same polynomial to several datasets. |
| `shared_polynomial_trend` | The polynomial coefficients are common; its amplitude and, optionally, its time offset are dataset-specific. | Share the shape of a trend while allowing each dataset to rescale or shift it. |
| `local_polynomial_trend` | `x_zero` and all coefficients are dataset-specific. | Fit an independent polynomial to each dataset using the same model definition. |
| `subset_polynomial_trend` | A separate reference time and set of coefficients are created for every subset in a dataset. | Fit independent polynomial trends to seasons, visits or other groups stored in one file. |

The alias `polynomial_trend_subset` is also accepted for
`subset_polynomial_trend`.

All four models use the `polynomial_trend` common object. PyORBIT creates this
object automatically when it is not explicitly included in the `common`
section.

## Model parameters

| Name | Scope | Models | Definition |
| --- | --- | --- | --- |
| `x_zero` | common | `polynomial_trend`, `shared_polynomial_trend` | Reference time $x_0$. |
| `x_zero` | dataset | `local_polynomial_trend` | Dataset-specific reference time $x_0$. |
| `x_zero_subN` | subset | `subset_polynomial_trend` | Reference time for subset `N`. |
| `poly_cN` | common | `polynomial_trend`, `shared_polynomial_trend` | Coefficient $c_N$ of the shared polynomial. |
| `poly_cN` | dataset | `local_polynomial_trend` | Dataset-specific coefficient $c_N$. |
| `poly_subM_cN` | subset | `subset_polynomial_trend` | Coefficient $c_N$ for subset `M`. |
| `poly_factor` | dataset | `shared_polynomial_trend` | Multiplicative amplitude of the shared polynomial. |
| `x_offset` | dataset | `shared_polynomial_trend` | Dataset-specific time translation. |

Default boundaries, spaces and priors are listed in
[Boundaries, spaces, and priors](../running_pyorbit/parameter_defaults.md#polynomial-and-detrending-models).

## Keywords

Model-wide keywords, with the default value in boldface.

**order**

* accepted values: integer up to `9` | **`1`**
* highest polynomial order $n$ included in the model

**starting_order**

* accepted values: integer between `0` and `order` | **`1`**
* lowest polynomial order $s$ included in the model; for most implementations,
  an explicit value overrides the choice made through `include_zero_point`,
  `exclude_zero_point` or `normalization_model`. In
  `shared_polynomial_trend`, enabling `variable_amplitude` forces the starting
  order back to one when it would otherwise be zero.

**include_zero_point**

* accepted values: `True` | **`False`**
* include the constant coefficient `poly_c0` by setting the starting order to
  zero; see the `variable_amplitude` interaction above for
  `shared_polynomial_trend`

**exclude_zero_point**

* accepted values: `True` | **`False`**
* exclude `poly_c0` by setting the starting order to one; this keyword is used
  by `polynomial_trend`, `shared_polynomial_trend` and
  `local_polynomial_trend`

**normalization_model**

* accepted values: `True` | **`False`**
* multiply the normalization component of the complete model instead of adding
  the polynomial to the dataset model; it also requests a starting order of
  zero before the other model-specific adjustments are applied

**time_interval**

* accepted values: any non-zero numerical value | **`1.0`**
* scale the time coordinate before evaluating the polynomial; for example,
  use `365.25` to express a time axis measured in days in units of years

**x_zero**

* accepted values: any value in the same units and reference system as the
  dataset times | **automatically selected**
* set the polynomial reference time; for `polynomial_trend`,
  `shared_polynomial_trend` and `local_polynomial_trend`, PyORBIT uses `Tref`
  when it lies within the relevant time span and otherwise uses an average
  dataset time. For a subset model, the corresponding keywords are
  `x_zero_sub0`, `x_zero_sub1`, and so on, and their defaults are the average
  times of the individual subsets.

The following keywords are specific to `shared_polynomial_trend`:

**variable_amplitude**

* accepted values: **`True`** | `False`
* add one dataset-specific `poly_factor` that multiplies the shared polynomial

**time_offset**

* accepted values: `True` | **`False`**
* add one dataset-specific `x_offset` to translate the shared polynomial along
  the time axis

**reference_dataset**

* accepted values: a dataset name
* when `time_offset: True`, fix `x_offset` to zero for the selected reference
  dataset

```{warning}
Including `poly_c0` in an additive polynomial may introduce a degeneracy with
the offset of the dataset. Unless the constant term is required, keep the
default `starting_order: 1`. When using a polynomial as a normalization model,
check whether the selected sharing scheme requires an explicit constant term.
```

## Examples

### One polynomial shared by several datasets

In this example the same linear and quadratic coefficients are used for both
datasets:

```yaml
inputs:
  RV_HARPS:
    file: datasets/HARPS.dat
    kind: RV
    models:
      - long_term_trend
  RV_HARPSN:
    file: datasets/HARPSN.dat
    kind: RV
    models:
      - long_term_trend

models:
  long_term_trend:
    model: polynomial_trend
    order: 2
    time_interval: 365.25
```

The common object can be declared explicitly when its boundaries, priors or
fixed values must be customized:

```yaml
common:
  long_term_polynomial:
    model: polynomial_trend
    boundaries:
      poly_c1: [-100.0, 100.0]
      poly_c2: [-20.0, 20.0]

models:
  long_term_trend:
    model: polynomial_trend
    common: long_term_polynomial
    order: 2
    time_interval: 365.25
```

### Independent polynomial for each dataset

Changing the model to `local_polynomial_trend` gives every dataset its own
reference time and coefficients. Generic boundaries in the model definition
are applied to each dataset:

```yaml
models:
  local_trend:
    model: local_polynomial_trend
    order: 2
    time_interval: 365.25
    boundaries:
      poly_c1: [-100.0, 100.0]
      poly_c2: [-20.0, 20.0]
```

Dataset-specific properties can be supplied in a subsection named after the
dataset:

```yaml
models:
  local_trend:
    model: local_polynomial_trend
    order: 2
    boundaries:
      poly_c1: [-100.0, 100.0]
      poly_c2: [-20.0, 20.0]
    RV_HARPS:
      boundaries:
        poly_c1: [-50.0, 50.0]
```

### Shared shape with dataset-specific amplitude and time offset

`shared_polynomial_trend` keeps the coefficients common while adding a
dataset-specific amplitude. The optional time shift must be anchored by a
reference dataset:

```yaml
models:
  shared_trend:
    model: shared_polynomial_trend
    order: 2
    time_interval: 365.25
    variable_amplitude: True
    time_offset: True
    reference_dataset: RV_HARPS
    boundaries:
      poly_factor: [-10.0, 10.0]
      x_offset: [-100.0, 100.0]
```

### One polynomial for each dataset subset

`subset_polynomial_trend` requires the sixth column of the input file to
contain the subset identifier, following the standard dataset format:

```text
# time value error jitter offset subset
59000.0  1.002  0.001  0  0  0
59001.0  0.999  0.001  0  0  0
59100.0  1.003  0.001  0  0  1
59101.0  1.001  0.001  0  0  1
```

The following model creates parameters such as `poly_sub0_c1`,
`poly_sub0_c2`, `poly_sub1_c1` and `poly_sub1_c2`:

```yaml
models:
  subset_trend:
    model: subset_polynomial_trend
    order: 2
    time_interval: 1.0
```
